# UMS IAM + HRMS Basic v1 — v1.0.0

> **Historical release-label notice:** This tag is retained as immutable release history. The combined UMS IAM Basic v1 + HRMS Basic v1 checkpoint is canonically labeled `v1.1.0`. See `docs/releases/v1.1.0.md`. The `v1.0.0` tag must not be moved, deleted, or overwritten.

## Release status

This document records the original combined-release labeling that was created as `v1.0.0`.

After review, the combined checkpoint was corrected to `v1.1.0` because UMS IAM Basic v1 had already been completed and frozen before HRMS Basic v1 capabilities were added. No application behavior is changed by that version correction.

## Shipped IAM baseline

UMS IAM Basic v1 provides the shared identity and access foundation used by the platform:

- authentication and session handling
- user administration
- organization and tenant context
- role and permission administration
- authorization enforcement through canonical permissions/authorities
- session administration and revocation support
- audit visibility
- authenticated React admin portal
- API Gateway as the browser-facing backend boundary

IAM Basic v1 is frozen except for genuine bug fixes. Post-v1 IAM enhancements are tracked separately.

## Shipped HRMS baseline

HRMS Basic v1 reuses IAM identity, session, JWT, organization context, permissions, and Gateway security. It does not introduce a second HRMS authentication system.

The shipped HRMS scope includes:

- Employee management
  - tenant-scoped list, create, detail, and update
  - immutable UMS user linkage
  - department and designation references
- Organization structure
  - department list/create/update
  - designation list/create/update
- Attendance
  - tenant-scoped list
  - create and update attendance records
  - employee/date/status/check-in/check-out/notes support
- Leave
  - tenant-scoped list and create
  - request state visibility
  - approve/reject/cancel transitions according to authority and state
- Payroll
  - salary structures
  - payroll runs
  - DRAFT -> PROCESSED -> FINALIZED lifecycle
  - generated payroll entries
  - payslip snapshot view
  - backend-returned gross/deduction/net values used as source of truth
- HRMS Admin Portal integration
  - Employees
  - Departments
  - Designations
  - Attendance
  - Leave
  - Payroll

## Security and request boundary

The browser communicates with backend capabilities through the API Gateway. HRMS screens reuse the existing IAM login/session and access token. Frontend permission checks control user experience only; backend services remain authoritative for authorization and tenant isolation.

Direct browser calls to internal HRMS service ports are not part of the supported architecture.

## Service and data boundaries

The platform follows service-owned data boundaries. IAM and HRMS services own their respective persistence models and do not rely on cross-service SQL joins or cross-service database foreign keys.

HRMS Basic v1 includes dedicated service boundaries for employee, attendance, leave, and payroll capabilities. Service-to-service ownership or identity validation is performed through service contracts rather than shared database access.

Flyway is used for versioned schema migration where database schema evolution is required.

## Platform infrastructure

The Basic v1 runtime uses:

- API Gateway for external API routing and trusted service boundary enforcement
- Eureka discovery for service registration/discovery
- Config Server for centralized runtime configuration
- RabbitMQ for the currently implemented asynchronous/audit integration points
- database-per-service ownership
- React/Vite admin portal for IAM and HRMS administration

Saga/orchestration is intentionally not used for ordinary CRUD flows. It remains reserved for future distributed business workflows that genuinely require coordinated multi-service state transitions.

## Known limitations and deferred work

The following were explicitly not part of this Basic v1 checkpoint and remain deferred unless delivered by a later release:

- MFA/TOTP and recovery flows
- advanced organization security policy and invitation lifecycle
- advanced session/device controls
- OAuth/OIDC expansion, SAML, SCIM, passkeys, and conditional access
- leave balance/accrual/carry-forward policy engine
- attendance shifts, rosters, or biometric integration
- payroll tax/PF/ESI/TDS calculations
- overtime, bonuses, reimbursements, arrears, bank/payment execution
- PDF payslip generation
- advanced HRMS dashboards and analytics
- production deployment/Kubernetes/cloud rollout
- package publication to Maven/npm registries

These items belong to post-v1 enhancement work and must not be treated as shipped capabilities of this historical release.
