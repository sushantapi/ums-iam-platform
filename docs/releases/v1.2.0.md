# UMS IAM + HRMS — v1.2.0

## Release status

`v1.2.0` is the next immutable v1 checkpoint after the canonical Basic v1 `v1.1.0` release.

This release keeps the previously shipped IAM + HRMS Basic v1 baseline and adds the IAM security/product enhancements that were merged afterward. Existing `v1.0.0` and `v1.1.0` tags/releases remain immutable and are not moved, deleted, or overwritten.

## Added since v1.1.0

### Secure password recovery

- enumeration-safe forgot-password flow
- single-use, time-limited password reset credentials
- SHA-256 digest-only reset-token persistence
- existing-session revocation after successful password reset
- exact public Gateway allow-list for forgot/reset endpoints
- Admin Portal forgot/reset password screens

### Password-reset delivery reliability

- bounded retry for password-reset email delivery
- dedicated sanitized terminal failure/DLQ topology
- no raw reset token/link persistence in terminal failure payloads
- finite retry behavior with explicit recovery verification

### Secure organization invitation lifecycle

- persisted invitation lifecycle with `PENDING`, `ACCEPTED`, `REVOKED`, and `EXPIRED`
- hash-only invitation-token persistence
- create/list/resend/revoke/accept flows
- token rotation on resend and replay/tamper/expiry/revocation protections
- matching authenticated-user email enforcement
- Admin Portal invitation management and secure browser handoff

### TOTP MFA and recovery codes

- RFC 6238 TOTP enrollment and verification
- encrypted TOTP secret persistence using external key material
- one-time recovery codes stored only as hashes
- MFA login challenge that issues no access/refresh token or login session before second-factor completion
- recovery-code rotation and MFA disable flows
- active-session revocation when MFA is disabled
- authenticated Admin Portal Security management screens

### Organization MFA security policy

- organization-owned `requireMfa` security policy
- Flyway-backed organization security-policy persistence
- tenant-authorized policy read/update APIs and Admin Portal UI
- organization-aware login enforcement
- platform-only enrollment session when organization MFA is required but the user has not enrolled MFA
- MFA-verified organization session issuance after challenge completion
- immediate and durable revocation of incompatible existing organization sessions when `requireMfa` is enabled
- trusted Gateway propagation of organization/MFA assurance with spoofed-header stripping

## Security and architecture guarantees

- API Gateway remains the browser-facing backend boundary
- service-owned databases and Flyway migrations remain the persistence model
- no cross-service SQL joins or shared-table ownership
- internal service calls remain protected by trusted service boundaries
- raw password-reset credentials, invitation bearers, TOTP secrets, recovery codes, MFA challenge tokens, JWTs, and internal secrets are excluded from logs/audit persistence by design
- existing platform `SUPER_ADMIN` semantics remain unchanged by organization MFA policy enforcement

## Verification baseline

The feature slices included in this release were merged only after their focused tests, required Backend/Frontend CI, security review, and local runtime acceptance gates passed.

The final organization MFA policy slice additionally verified:

- Gateway health and registration
- bounded user-profile readiness before organization creation
- organization creation and legacy policy-off access
- policy enablement and revocation of non-MFA organization sessions
- platform-only MFA enrollment behavior
- spoofed organization/MFA assurance header rejection
- TOTP enrollment and challenge verification
- MFA-verified organization access
- cleanup/revocation behavior
- final runtime marker `ISSUE_34_ORGANIZATION_MFA_RUNTIME_GATE=PASS`

The `v1.2.0` release-notes PR must keep required Backend CI and Frontend CI green. The release itself must be created only from the exact approved `main` commit using the repository Release workflow.
